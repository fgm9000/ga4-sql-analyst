# ADR 004 — LLM Evaluation Strategy

> 🇺🇸 EN | 🇧🇷 [PT-BR](004-llm-evaluation-strategy.pt-BR.md) · Status: Accepted (Gate 2, 2026-11-13) · Date: 2026-11-13

## Context
PRD Section 8 defines 4 core quality evaluation metrics: result equivalence accuracy, adversarial block recall (CI gate), grounded summary numbers, and deterministic date anchor resolution. Result equivalence executes SQL against a test warehouse and compares DataFrames (`pandas.testing`), which is inherently native to Python. While the Master Standard used Promptfoo in Demo 1, this project expands portfolio repertoire and brings evals inside the typed Python quality ratchet.

## Considered Options
| Option | Pros | Cons |
|---|---|---|
| A — Promptfoo (Standard) | Broadly recognized; built-in web side-by-side viewer | Already proven in Demo 1; YAML configuration lives outside strict type checks; requires Node/npx in CI |
| B — **`pydantic_evals`** | Typed Python datasets and evaluators checked by `mypy --strict`; zero Node dependencies in CI; precision/recall measurement on guardrails | No default GUI viewer (Markdown artifact generated instead); coupling to Pydantic ecosystem |
| C — Both | — | Unjustified tooling redundancy |

## Decision
Adopt `pydantic_evals` in place of Promptfoo, pinned to exact versions in `uv.lock`.

## Justification
- **Repertoire Diversification:** Demonstrates mastery across multiple evaluation ecosystems (Demo 1 with Promptfoo, Demo 2 with `pydantic_evals`).
- **Unified Language Runtime:** Evaluators and datasets are strictly typed Python code covered by the 100% CI quality ratchet.
- **Bi-directional Guardrail Evaluation:** Measures both recall (100% of malicious attacks blocked) and false block rate (0% of legitimate business queries rejected).

## Implementation Design
- `evals/`: Structured evaluation datasets covering canonical questions, date anchor edge cases, and adversarial injections.
- Custom Evaluators: `ResultEquivalence` (pandas DataFrame comparison), `SummaryNumbersGrounded`, `DateAnchorCorrect`.
- CI Job (`eval-offline`): Executes offline against DuckDB and deterministic `FunctionModel` snapshots; gates merge if adversarial recall < 1.000 or false block rate > 0.000.
- Workflow (`eval-live.yml`): Dispatched on-demand against live Vertex AI and BigQuery.

## Consequences
- Positive: No Node runtime required in CI runner; full integration with `mypy --strict` and `pytest`.
- Trade-off: Markdown reports generated by custom script instead of built-in web viewer.
